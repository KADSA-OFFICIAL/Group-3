# 서버 실행 가이드

젤리 워즈의 **PC 판은 온라인 전용**입니다. **전용 헤드리스 서버**가 판정하고, PC 2대가
Tailscale로 접속합니다(이슈 #361). 방은 1번·2번 둘입니다(이슈 #409). **안드로이드 판은 지금처럼 한 화면 2인 오프라인 전용**이라
서버가 필요 없습니다. 기기가 모드를 정하고 화면에서 고르는 곳은 없습니다.

이 문서는 서버를 띄우는 사람이 보는 문서입니다. 게임 구조 전체는 [CLAUDE.md](../CLAUDE.md)를 보세요.

## 방은 1번·2번 둘

서버 프로세스 하나 = 방 하나 = UDP 포트 하나입니다(`scripts/network.gd`의 `ROOMS`).

| 방 | 포트 | 서버 실행 인자 |
|---|---|---|
| 1번 방 | UDP 7777 | `--server --room=1` (`--room` 을 빼도 1번 방) |
| 2번 방 | UDP 7778 | `--server --room=2` |

방끼리 프로세스가 달라 완전히 독립입니다 — 한 방에서 경기가 진행 중이어도 다른 방은
두 사람을 받고, 한 방 서버가 죽어도 다른 방은 영향이 없습니다.
1 VS 1 이므로 한 방에 두 사람이 들어오면 꽉 찹니다. 세 번째로 접속하면 타이틀에
`자리가 꽉 찼습니다 (1 VS 1).`이 뜨고, 경기 중에 접속하면 `경기가 진행 중입니다.`가 뜹니다.
그때는 **다른 방**을 누르면 됩니다.

#320 이전에 있던 **3번 방, 관전, 버전 악수는 되살리지 않았습니다.**

## 지금 서버는 개발 맥

서버컴에 접근할 수 없어 **개발 맥(Tailscale `100.84.71.63`)이 서버를 대신 돕니다**(이슈 #412).
클라이언트의 기본 주소(`Network.DEFAULT_ADDRESS`)도 그 주소입니다. 맥에는 `run-server.bat` 이
안 돌아가므로 아래 "손으로 띄우기"의 명령을 방마다 하나씩 띄웁니다(`--room=1`, `--room=2`).
**맥이 켜져 있고 잠자기에 들어가지 않아야** 접속되며, macOS 방화벽이 Godot 의 수신을 막지
않아야 합니다. 서버컴이 돌아오면 `DEFAULT_ADDRESS` 를 `100.102.216.35` 로 되돌립니다.

## 서버 띄우기

서버컴에서 저장소 루트의 **`run-server.bat` 을 더블클릭**하면 끝입니다. **방마다 콘솔 창이
하나씩(1번 방·2번 방, 모두 둘)** 열리고 그 안에서 헤드리스 서버가 뜹니다.

- **띄우기 전에 최신 게임 파일을 스스로 받습니다** — `origin/main` 으로 맞춥니다.
  **서버와 클라이언트가 같은 코드여야 합니다** — 아래 "버전이 다르면" 참고.
  실행할 때마다 **`지금 도는 코드: <브랜치> <해시>`** 가 찍힙니다.
- 일부러 다른 브랜치로 띄우려면 `SERVER_BRANCH` 를 먼저 지정합니다.

  ```
  set SERVER_BRANCH=feat-361-online-mode
  run-server.bat
  ```

- **사람이 만든 작업은 지우지 않습니다.** `main` 에 없는 로컬 커밋이나 커밋되지 않은
  변경이 있으면 최신화를 **건너뛰고** 사유를 알립니다. 그때 서버는 옛 코드로 뜹니다.
- Godot 콘솔 바이너리는 스크립트가 스스로 찾습니다 — 환경변수 `GODOT`, 프로젝트 폴더,
  `%USERPROFILE%\Downloads` 순서입니다.
- 서버가 죽어도 그 창은 남습니다. 끄려면 방마다 그 창에서 `Ctrl+C` 를 누르거나 창을 닫습니다.
- 이미 7777·7778 중 하나를 쓰는 프로세스가 있으면 **그 포트를 알려 주는 경고**가 뜨고,
  그 방의 새 창은 곧 실패합니다. 다른 방은 영향이 없습니다.

**스크립트를 고칠 때는 저장 인코딩을 건드리지 마세요.** `run-server.bat` 은
CP949(ANSI 한국어) + CRLF 입니다. UTF-8 로 저장하면 cmd 의 배치 파서가 어긋나
줄 중간부터를 명령으로 실행합니다. 이유는 파일 머리말과 `.gitattributes` 에 적혀 있습니다.

### 손으로 띄우기

```bash
"Godot_v4.6.2-stable_win64_console.exe" --headless --path . -- --server            # 1번 방
"Godot_v4.6.2-stable_win64_console.exe" --headless --path . -- --server --room=2   # 2번 방
```

- **`--room=` 값은 `ROOMS` 의 번호(1, 2)여야 합니다.** 그 밖이면 서버가 바로 종료됩니다 —
  오타 난 값이 조용히 1번 방으로 뜨지 않게 하려는 것입니다.
- **`--server` 가 있어야 서버가 됩니다.** 헤드리스로 띄우는 것만으로는 서버가 아니라
  오프라인 게임이 돕니다 — 커밋 전 헤드리스 검증([CLAUDE.md](../CLAUDE.md))을 위해서입니다.
- 서버는 대기실을 거치지 않고 전투 화면에 머물며 두 사람을 기다립니다. 정상입니다.

기동에 성공하면 이렇게 찍힙니다.

```
서버 시작 — 1번 방, 포트 7777, 플레이어 2명
서버 시작 — 2번 방, 포트 7778, 플레이어 2명
```

(두 줄은 각 방의 창에 하나씩 찍힙니다.) 이 줄이 안 보이면 그 방 서버가 뜬 게 아닙니다. 접속·경기 진행도 로그에 남습니다.

```
피어 216843833 입장 (1P)
피어 613579963 입장 (2P)
경기 시작 — [216843833, 613579963]
경기 종료
```

## 방화벽

서버컴 Windows 방화벽에 **UDP 7777·7778** 인바운드 허용이 있어야 합니다. **2번 방을 새로 여는
서버컴이라면 7778 규칙을 추가해야 접속됩니다.**

## 클라이언트에서 접속

**PC 에서 게임을 켜고 타이틀의 `1번 방` 또는 `2번 방`을 누르면 끝입니다.** 서버 주소는 입력하지
않습니다. 누른 방의 포트로 붙습니다.

- **기기에 Tailscale 이 켜져 있어야 합니다** — 서버 주소(`scripts/network.gd`의
  `DEFAULT_ADDRESS`)가 tailnet 안에서만 닿는 주소입니다.
- 접속하면 캐릭터 선택 창이 **대기실**로 열립니다. 자기 패널만 고를 수 있고, 상대가
  고른 캐릭터는 상대 패널에 보입니다. 둘 다 `준비`를 누르면 서버가 경기를 시작합니다.
- 무기는 라운드마다 **두 사람이 동시에** 각자 기기에서 고릅니다(상대 카드는 안 보입니다).
- 조작은 `WASD`+왼쪽 `Shift` 와 방향키+`Space` **어느 쪽이든** 됩니다 — 1P·2P 자리와 상관없습니다.
- 경기가 끝나면 둘 다 대기실로 돌아옵니다. 상대가 나가면 남은 사람은 대기실로
  돌아와 `상대가 나가서 경기를 끝냈습니다.`를 보고 새 상대를 기다립니다.
- **서버 주소가 바뀌면 코드를 고치고 배포본을 다시 만들어야 합니다**([build.md](build.md)).
- **로컬 서버로 테스트할 때**는 `--address=127.0.0.1`을 붙여 실행하고, 서버도 같은 방 번호로 띄웁니다
  (`--server --room=2` 서버에는 타이틀의 `2번 방` 버튼).

  ```
  JellyWars.exe --address=127.0.0.1
  ```

- PC 에서 오프라인 흐름을 확인해야 할 때만 `--offline` 을 붙입니다(개발·검증용).
  배포본 사용자에게 안내하는 길이 아닙니다.

## 버전이 다르면

**서버와 클라이언트는 반드시 같은 코드로 돌아야 합니다.** RPC 는 함수 이름이 아니라
번호로 오가므로, 한쪽에만 `@rpc` 함수가 하나 더 있으면 번호가 밀려 **엉뚱한 함수가
불립니다** — 무기 카드가 안 뜨거나 젤리가 멈춰 있는 식으로, 원인과 먼 증상이 납니다.
#320 이전에는 접속할 때 이것을 막는 버전 악수(#228)가 있었지만 이번에는 되살리지 않았습니다.

이상한 증상이 보이면 먼저 **`run-server.bat` 을 다시 돌리고**(서버를 `origin/main` 으로
맞춤) 클라이언트도 `main` 으로 다시 빌드한 것을 쓰세요.

## 문제 해결

**서버가 바로 꺼지고 `서버 시작 실패 (1번 방, 포트 7777): ...`가 뜬다**
그 포트로 서버가 이미 떠 있습니다(2번 방이면 포트 7778). 남아 있는 프로세스를 끄세요. 포트를 못 열면 프로세스는
**일부러 종료**됩니다(exit code 1).

**타이틀에 "접속하지 못했습니다 — 서버나 Tailscale 이 꺼져 있습니다."**
서버가 안 떠 있거나, 이 기기의 Tailscale 이 꺼져 있거나, 방화벽이 막고 있습니다.
8초(`Network.JOIN_TIMEOUT_SEC`) 동안 답이 없으면 이렇게 뜹니다.

**대기실에서 "상대를 기다리는 중..."에서 안 넘어간다**
상대가 아직 안 붙었습니다. 서버 로그의 `입장` 줄이 둘인지 확인하세요.

**상대가 강제 종료됐는데 한동안 그대로다**
프로세스가 그냥 죽으면(강제 종료·랜선 뽑기) 서버가 응답 없음을 시간을 재서 알아차립니다
(ENet 기본값으로 몇 초, 길면 30초쯤). 그동안은 나간 사람이 아직 있는 것으로 보입니다.

## 방 추가하기

`scripts/network.gd`의 `ROOMS` 에 줄을 더하고, **`run-server.bat` 도 같이 고칩니다**(포트 변수·
`start` 줄 — 배치 파일은 `ROOMS` 를 읽지 못합니다. 인코딩은 CP949 + CRLF 를 지킵니다).
타이틀의 방 버튼은 씬에 방마다 따로 놓여 있어서(`title.tscn`·`title.gd`) 버튼도 더해야 합니다.
서버컴 방화벽에 새 포트를 UDP 로 열어야 합니다.
