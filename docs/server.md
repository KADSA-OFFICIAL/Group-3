# 서버 실행 가이드

젤리 워즈는 **전용 헤드리스 서버**가 권위를 갖고, 클라이언트 2대가 Tailscale로 접속하는 구조입니다.
이 문서는 서버를 띄우는 사람이 볼 문서입니다. 게임 구조 전체는 [CLAUDE.md](../CLAUDE.md)를 보세요.

## 방 = 포트 = 프로세스

방 하나가 서버 프로세스 하나입니다. 포트로 구분하고, 방끼리는 완전히 독립적입니다 —
한 방이 죽어도 다른 방은 영향을 받지 않습니다. **방을 2개 쓰려면 서버를 2개 띄워야 합니다.**

방 목록의 유일한 출처는 [`scripts/network.gd`](../scripts/network.gd)의 `ROOMS`입니다.

| 방 | 포트 |
|---|---|
| 1번 방 | 7777 |
| 2번 방 | 7778 |

방 하나당 정원은 **플레이어 `MAX_PLAYERS`(2명) + 관전 `MAX_OBSERVERS`(4명)** 입니다.
ENet 에 넘기는 값은 둘을 합한 `MAX_CLIENTS`(6명)이고, 셋 다 `scripts/network.gd`에 있습니다.
서버 자신은 플레이어가 아닙니다.

## 관전(옵저버)

1P·2P와 **독립된 기기**로 같은 방에 들어가 경기를 지켜볼 수 있습니다(이슈 #167).
**관전은 실행 파일이 다릅니다** — `JellyWars-Observer.exe`로 실행하면 항상 관전자입니다(이슈 #180).
화면에서 역할을 고르는 곳은 없습니다. 두 실행 파일을 만드는 방법은 [build.md](build.md)에 있습니다.

- 관전자는 플레이어 자리를 차지하지 않습니다 — 관전자가 3명 있어도 플레이어 자리는 2개 그대로입니다.
- 대기실에서는 양쪽 선택을 **보기만** 합니다(패널·준비 버튼이 모두 잠깁니다).
- 두 플레이어가 준비하면 관전자도 함께 전투 화면으로 들어가고, 경기가 끝나면 함께 대기실로 돌아옵니다.
- 관전 중 ESC로 언제든 나갈 수 있고, 나가도 진행 중인 경기에 영향이 없습니다.
- **방을 아무 때나 옮길 수 있습니다**(이슈 #184) — 대기실이든 전투 화면이든 화면 위의
  `관전: 1번 방` 옆에 있는 다른 방 버튼을 누르면 그 방으로 넘어갑니다. 주소는 처음 접속할 때
  쓴 것을 그대로 씁니다. 경기 두 개를 번갈아 보려면 이 버튼만 누르면 됩니다.
  옮겨간 방 서버가 꺼져 있거나 정원이 찼으면 타이틀 화면으로 돌아가고 사유가 뜹니다 —
  **먼저 끊고 붙는 구조라 원래 방으로 자동 복귀는 못 합니다.** 그때는 다시 접속하세요.
- **경기 도중에 들어가도 그 경기를 봅니다**(이슈 #182) — 대기실을 스치고 바로 전투 화면에
  들어가며, 체력·점수도 지금 상태로 맞춰서 보입니다.
- **플레이어는 경기 도중에 끼어들지 않습니다** — 경기 중에 빈 자리를 받으면 대기실에서
  `경기가 진행 중입니다`를 보고 기다립니다. 진행 중인 경기에 들어가는 것은 관전자뿐입니다.
- 플레이어 자리가 찬 방에 `플레이어`로 들어가면 대기실 화면에 사유가 뜹니다.
  **역할은 화면에서 못 바꿉니다** — 관전으로 보려면 `JellyWars-Observer.exe`로 다시 접속하세요.
  그대로 기다려도 됩니다. 플레이어 한 명이 나가면 그 자리를 자동으로 받습니다.

서버 로그에 역할이 찍히므로 누가 어느 자리로 들어왔는지 확인할 수 있습니다.

```
피어 1234567890 관전 입장 (관전 1명)
피어 1876543210 플레이어 입장 (1P)
```

## 서버 띄우기

저장소 루트의 **`run-server.bat` 를 더블클릭**하면 끝입니다. `ROOMS` 에 적힌 방마다
콘솔 창이 하나씩 열리고 그 안에서 헤드리스 서버가 뜹니다. 창 제목에 몇 번째 방인지와
포트가 적혀 있습니다.

- **방을 띄우기 전에 최신 게임 파일을 스스로 받습니다** — **`origin/main`** 으로
  맞춥니다. 옛 파일로 서버가 떠 있으면 최신 클라이언트가 접속해도 입장이 안 되므로,
  서버컴에서 직접 `git pull`을 챙기지 않아도 되게 한 것입니다. 체크아웃이 다른
  브랜치에 남아 있어도 `main` 으로 옮겨 붙습니다 — 예전에는 "지금 브랜치"로 맞춰서,
  서버컴이 기능 브랜치에 주차되면 **재시작을 몇 번 해도 최신 코드를 못 받으면서
  화면에는 "최신화 됨"으로 나왔습니다**(이슈 #234). 인터넷이 안 되거나 git이 없으면
  경고만 뜨고 있는 파일 그대로 뜹니다. 커밋이 바뀌었으면 Godot 클래스 캐시도 자동으로
  다시 만듭니다. 실행할 때마다 **`지금 도는 코드: <브랜치> <해시>`** 가 찍히므로,
  서버가 어느 코드로 도는지는 그 줄을 보면 됩니다.
- **일부러 다른 브랜치로 서버를 띄우려면** `SERVER_BRANCH` 를 먼저 지정합니다.
  그때는 기본값이 아니라는 알림이 함께 뜹니다.

  ```
  set SERVER_BRANCH=feat-231-punch-windup
  run-server.bat
  ```

- **사람이 만든 작업은 지우지 않습니다.** 최신화 대상에 없는 로컬 커밋이 있거나
  커밋되지 않은 변경이 있으면 최신화를 **건너뛰고** 사유를 알립니다. 이 폴더는 개발
  체크아웃도 겸하기 때문입니다. 그때는 서버가 옛 코드로 뜨므로, 안내대로 `push` 해서
  `main` 에 머지하거나 변경을 되돌린 뒤 다시 실행하세요. (`.import` 파일은 Godot이
  LF로 다시 써서 상시 어긋나는 잡음이라 세지 않습니다.)
- Godot 콘솔 바이너리는 스크립트가 스스로 찾습니다 — 환경변수 `GODOT`, 프로젝트 폴더,
  `%USERPROFILE%\Downloads` 순서입니다. 못 찾으면 창을 닫지 않고 어디에 두면 되는지
  알려 줍니다. 다른 곳에 두었다면 `set GODOT=D:\godot\Godot_..._console.exe` 를 먼저
  실행하고 이어서 `run-server.bat` 을 실행하세요.
- 포트는 [`scripts/network.gd`](../scripts/network.gd) 의 `ROOMS` 에서 읽습니다.
  **방을 늘려도 스크립트는 고치지 않습니다** — `ROOMS` 에 줄을 추가하면 그 방까지 함께 뜹니다.
- 이미 그 포트를 쓰고 있으면 띄우기 전에 경고가 뜹니다.
- 서버가 죽어도 그 창은 남습니다 — 실패 메시지를 읽을 수 있습니다.
- 서버를 끄려면 그 방의 창에서 `Ctrl+C` 를 누르거나 창을 닫습니다.

**스크립트를 고칠 때는 저장 인코딩을 건드리지 마세요.** `run-server.bat` 은
CP949(ANSI 한국어) + CRLF 입니다. UTF-8 로 저장하면 cmd 의 배치 파서가 어긋나
줄 중간부터를 명령으로 실행합니다. 이유는 파일 머리말과 `.gitattributes` 에 적혀 있습니다.

### 손으로 띄우기

스크립트를 쓰지 않으려면 Godot 콘솔 바이너리로 프로젝트 폴더를 지정해 실행합니다.
창 없이 뜨고, 로그는 콘솔에 나옵니다.

```bash
"Godot_v4.6.2-stable_win64_console.exe" --headless --path . --port=7777
```

```bash
"Godot_v4.6.2-stable_win64_console.exe" --headless --path . --port=7778
```

- `--port=`를 생략하면 **1번 방(7777)** 으로 뜹니다.
- `--port=`는 `--` 뒤에 붙여도 됩니다(`--headless --path . -- --port=7778`).
- 두 방을 다 쓰려면 위 두 줄을 **각각 다른 콘솔 창에서** 실행합니다.
- 헤드리스로 뜨면 서버는 대기실을 거치지 않고 전투 화면에 계속 머뭅니다. 정상입니다.

기동에 성공하면 이렇게 찍힙니다.

```
서버 시작 — 2번 방, 포트 7778, 플레이어 2명 + 관전 4명
```

이 줄이 안 보이면 서버가 뜬 게 아닙니다.

## 방화벽

서버컴 Windows 방화벽에 **UDP 7777과 7778을 모두** 인바운드 허용해야 합니다.
`ROOMS`에 방을 추가했다면 그 포트도 함께 열어야 합니다.

## 클라이언트에서 접속

**방을 고르고 `접속`을 누르면 끝입니다.** 서버 주소는 입력하지 않습니다(이슈 #198).
역할은 실행한 파일이 정합니다 — 관전으로 보려면 `JellyWars-Observer.exe`를 실행하세요([build.md](build.md)).

- 서버 주소는 코드(`scripts/network.gd`의 `DEFAULT_ADDRESS`)에 박혀 있고, 접속 화면은 그 값을
  **글자로 보여주기만** 합니다. 서버가 하나뿐이고 방은 포트로만 갈리므로 고를 것이 없습니다.
- **서버 주소가 바뀌면 코드를 고치고 배포본을 다시 만들어야 합니다.** 화면에서 바꿀 방법이
  없으므로, 주소가 바뀌면 새 exe를 팀에 다시 나눠 줘야 합니다([build.md](build.md)).
- **로컬 서버로 테스트할 때**는 `--address=127.0.0.1`을 붙여 실행합니다.
  ```
  JellyWars.exe --address=127.0.0.1
  ```
- 기기 한 대만 다른 서버에 붙여야 하면 `%APPDATA%\Godot\app_userdata\Jelly Wars\client.cfg`에
  이렇게 적어 둡니다(실행 인자가 이 파일보다 우선합니다). 이 파일은 기기마다 다르고
  저장소·배포본에 들어가지 않습니다.
  ```
  [server]

  address="192.168.0.10"
  ```
- 기본 주소가 아닌 값이 쓰이면 접속 화면에 `(예외 설정)`이 함께 표시됩니다 — 위 두 가지가
  걸려 있는지 화면에서 바로 알 수 있습니다.
- 같은 방에 들어간 2명이 각자 준비를 누르면 서버가 경기를 시작시킵니다.

## 문제 해결

**서버가 바로 꺼지고 `서버 시작 실패 (포트 7777): Can't create`가 뜬다**
그 포트로 서버가 이미 떠 있습니다. 남아 있는 프로세스를 끄거나 다른 `--port=`를 쓰세요.
포트를 못 열면 프로세스는 **일부러 종료**됩니다(exit code 1) — 반쪽짜리로 살아남아
"떠 있는 줄 알았는데 아무도 못 들어오는" 상태를 만들지 않기 위해서입니다.

**접속 화면에서 "서버가 오래된 버전입니다" 또는 "게임 버전이 서버와 다릅니다"**
서버가 도는 코드와 클라이언트의 코드가 다릅니다(이슈 #228). **`run-server.bat` 을 다시
돌리세요** — 그것이 `origin/main` 으로 맞추고 캐시까지 다시 만듭니다. 코드를 받기만 하고
다시 켜지 않으면 이미 떠 있는 프로세스는 옛 코드 그대로입니다.

다시 돌렸는데도 안 풀리면 **콘솔에 찍힌 `지금 도는 코드:` 줄과 최신화 경고를 먼저 보세요.**
최신화를 건너뛴 경우(커밋되지 않은 변경, `main` 에 없는 로컬 커밋)에는 사유가 적혀 있고,
서버는 옛 코드로 뜬 상태입니다. 그 안내를 처리한 뒤 다시 돌려야 풀립니다.
그것까지 정상인데도 다르면 이번에는 클라이언트 쪽이 뒤처진 것이니 배포본을 새로 받으세요.

서버 시작 로그의 마지막 칸(`... 관전 4명, 버전 db78909c...`)이 서버의 버전 값이고,
거부 메시지에 서버 값과 이 기기 값이 함께 나오므로 어느 쪽이 다른지 견줄 수 있습니다.

이 검사가 없던 시절에는 어긋난 접속이 **그냥 통과했습니다.** RPC 는 함수 이름이 아니라
자리 번호로 오가기 때문에, 한쪽에만 함수가 하나 더 있으면 번호가 밀려 엉뚱한 함수가
불렸습니다 — 실제로 "무기 선택 창이 안 뜨고 두 젤리가 가만히 서 있다가 20초 뒤 무기가
저절로 정해지는" 증상으로 나타났습니다. 지금은 접속 단계에서 막습니다.

**접속 화면에서 "접속하지 못했습니다. 방이 꽉 찼거나 서버가 꺼져 있습니다."**
그 방에 이미 6명(플레이어 2 + 관전 4)이 있거나, 그 포트의 서버가 안 떠 있습니다.
방이 꽉 찬 경우 ENet은 거절 신호를 보내지 않고 조용히 무시하므로, 클라이언트가 8초를 기다린 뒤
직접 실패로 처리합니다. 다른 방을 고르거나 서버 로그를 확인하세요.

**접속은 되는데 상대가 안 보인다**
서로 **다른 방**에 들어갔을 수 있습니다. 양쪽이 같은 방 버튼을 골랐는지 확인하세요.
한쪽이 `관전`으로 들어갔을 수도 있습니다 — 관전자는 플레이어 자리에 앉지 않으므로
상대는 계속 `상대 대기 중...`을 봅니다. 서버 로그의 역할 줄로 확인하세요.

**대기실에서 아무것도 눌리지 않고 "대기실 정보를 받는 중..."에서 멈춘다**
서버가 아직 역할을 배정하지 않은 상태입니다. 클라이언트가 1초마다 다시 청하므로 보통 곧 풀립니다.
계속 멈춰 있으면 접속이 끊긴 것이니 `홈`으로 나가서 다시 접속하세요.

**대기실에 "경기가 진행 중입니다"가 뜨는데 실제로는 아무도 안 싸우고 있다**
경기 중에 클라이언트가 **끊기지 않고 죽었을 때**(에디터 디버깅 중지, 강제 종료, 랜선 뽑기)
생기던 증상입니다. 서버는 싸울 사람이 2명 미만이 되면 판을 접고 `상대가 나가서 경기를 끝냅니다`를
띄운 뒤 모두를 대기실로 돌려보냅니다 — 잠깐 기다리면 풀립니다.

- 정상 종료(ESC·창 닫기)는 즉시 알려지지만, **프로세스가 그냥 죽으면 서버가 응답 없음을
  시간을 재서 알아차립니다**(ENet 기본값으로 보통 몇 초, 길면 30초쯤). 그 시간만큼은
  나간 사람이 아직 그 자리에 있는 것으로 보입니다.
- 아직 아무도 전투 화면에 스폰되기 전이었다면 15초(`main.gd` 의 `ABANDON_GRACE_SEC`)를
  더 기다린 뒤 접습니다 — 경기 시작 직후 씬을 불러오는 중인 것과 구별할 방법이 없어서입니다.
- 그래도 계속 "경기가 진행 중입니다"에서 안 풀리면 그 방 서버를 끄고 다시 띄우세요.

## 방 추가하기

`scripts/network.gd`의 `ROOMS`에 줄을 추가하면 됩니다.

