# 젤리 워즈 (Jelly Wars)

팀 **스틱매너** 의 **온라인 2인 대전** 액션 게임. 두 플레이어가 각자의 기기로 접속해 여러 무기로 대전하며, 3점을 먼저 얻으면 승리한다.

- **엔진:** Godot 4.5
- **장르:** 액션 (온라인 2인 대전)

## 실행 방법

1. Godot 4.5 이상을 실행한다.
2. 프로젝트 매니저에서 **가져오기(Import)** → 이 폴더의 `project.godot` 선택.
3. **F5** 를 누르면 타이틀 화면부터 시작된다.

## 포트 번호 — 아직 정해지지 않음

**팀에서 쓸 포트 번호가 정해지지 않아서 코드 어디에도 기본값을 넣지 않았다.**
로비 화면의 포트 칸, 전용 서버의 `--port`, 도커의 `JELLY_PORT` 모두 값을 직접 넣어야 하고, 비우면 실행되지 않는다.
번호가 정해지면 `server/.env` 와 팀 공유 문서에만 적으면 된다.

## 온라인으로 붙는 법

두 명 중 한 명이 방을 열고, 다른 한 명이 그 주소로 접속한다.

1. 타이틀에서 **온라인 대전**.
2. 한 명이 **포트**를 넣고 **방 열기** → 상대에게 자기 IP 와 포트를 알려준다.
3. 다른 한 명이 **서버 주소** 와 **포트** 를 넣고 **접속**.
4. 두 명이 다 붙으면 **자동으로** 캐릭터 선택 창으로 넘어간다.
5. 각자 자기 캐릭터를 고르고 **준비** 를 누른다. **양쪽이 다 준비하면 자동으로 전투가 시작된다.**

맵은 고르지 않는다 — 매치가 시작될 때 구현된 맵 중에서 무작위로 정해진다.

같은 와이파이면 방을 연 사람의 사설 IP(예: `192.168.0.5`)를 그대로 쓰면 된다.
서로 다른 네트워크에 있으면 방을 연 쪽이 공유기에서 포트를 포워딩해야 하므로, 아래 전용 서버 방식이 더 편하다.

## 전용 서버

서버만 따로 돌리면 두 플레이어 모두 포트 포워딩 없이 접속할 수 있다.
방장 개념이 없어서 리슨 서버든 전용 서버든 플레이어가 하는 일은 같다.

직접 실행하는 경우:

```bash
godot --headless --path . -- --server --port=<포트번호>
```

### 도커로 돌리기 (윈도우)

Docker Desktop(WSL2 백엔드)이 필요하다. 프로젝트 폴더는 읽기 전용으로 마운트되고 컨테이너가 내부로 복사해서 쓰므로, 컨테이너가 프로젝트 폴더를 건드리지 않는다.

```bash
cp server/.env.example server/.env
```

`server/.env` 를 열어 `JELLY_PORT` 에 포트 번호를 채운 뒤:

```bash
docker compose -f server/docker-compose.yml up --build
```

코드를 고쳤으면 재빌드 없이 컨테이너만 다시 시작하면 된다 (시작할 때마다 프로젝트를 다시 복사·임포트한다).

```bash
docker compose -f server/docker-compose.yml restart
```

**주의할 점**

- ENet 은 **UDP** 를 쓴다. 포트를 직접 열 때 `-p <포트>:<포트>/udp` 처럼 `/udp` 를 반드시 붙여야 한다. 빠뜨리면 서버는 정상으로 보이는데 아무도 접속하지 못한다. `docker-compose.yml` 에는 이미 붙어 있다.
- **도커는 NAT 를 뚫어주지 않는다.** 집 공유기 뒤의 PC 에서 돌린다면 밖에서 붙으려면 공유기에서 해당 UDP 포트를 그 PC 로 포워딩하고, 공인 IP 또는 DDNS 주소를 팀에 알려줘야 한다.
- 윈도우 방화벽이 Docker Desktop 의 인바운드 UDP 를 막을 수 있다. 처음 실행할 때 허용해야 한다.

### 개발용 로컬 2인

노트북 두 대 없이 혼자 테스트할 때는 타이틀의 **로컬 2인 (개발용)** 을 쓴다. 네트워크를 타지 않고 한 화면에서 두 캐릭터를 조작한다.

## 조작

| | 온라인 (각자 자기 기기) | 로컬 2인 테스트 1P | 로컬 2인 테스트 2P |
|---|---|---|---|
| 좌우 이동 | ← / → | A / D | ← / → |
| 점프 | ↑ | W | ↑ |
| 빠른 낙하 | ↓ | S | ↓ |
| 스킬 | Shift | Space | Shift |

> 로컬 테스트 1P 만 Shift 가 아니라 Space 를 쓴다. Godot 의 InputMap 은 키 이벤트의 좌/우
> 위치(`location`)를 무시해서 왼쪽/오른쪽 Shift 를 다른 액션으로 나눌 수 없기 때문이다.
> 온라인에서는 각자 자기 기기를 쓰므로 양쪽 다 계획서대로 Shift 다.

전투 중 **ESC** 를 누르면 연결을 끊고 타이틀로 돌아간다.

## 화면 흐름

```
타이틀 ─┬─ 온라인 대전 → 로비(방 열기/접속) ──[두 명 접속]──┐
        └─ 로컬 2인 (개발용) ─────────────────────────────┴→ 선택 창 ─[양쪽 준비]─→ 전투
```

화면 전환은 전부 서버가 결정해서 전원에게 동시에 내린다 (`Net.phase`: LOBBY → SELECT → MATCH).

## 네트워크 구조

- **전송:** ENet (`ENetMultiplayerPeer`), UDP. 포트는 미정이라 기본값 없음.
- **서버:** 리슨 서버(플레이어가 겸함) / 전용 서버 둘 다 같은 코드로 동작한다.
- **진행 제어:** 방장 없이 서버가 접속·준비 상태만 보고 다음 단계로 넘긴다.
- **캐릭터 움직임:** 각 피어가 자기 젤리만 시뮬레이션하고 위치·속도·방향을 `MultiplayerSynchronizer` 로 보낸다.
- **서버 단독 판정:** 피격, 막기, 상태이상, 버프, 쿨타임, 라운드 점수. 양쪽에서 결과가 갈리면 안 되기 때문이다.

## 전투 규칙 요약

**핵심 루프** (계획서): `[무기 선택 → 라운드 → 승리자 1점] → 3점 선취 승리`

라운드가 시작되기 전마다 전투 화면 위에 무기 선택 창이 뜬다. **17종 중 랜덤 3개**가 제시되고
**두 플레이어는 서로 다른 후보**를 받는다. **10초** 안에 안 고르면 후보 중에서 자동으로 정해진다.

- 기본 공격은 **자동**이다. 무기가 상대에 닿으면 들어간다. 폭탄·샷건은 기본 공격이 없다.
- 특수 공격은 **Shift**, 바라보는 방향으로만 나간다. 쿨타임은 무기 도형 색으로 표시된다.
- **막기:** 상대를 보고 있고 내 무기가 상대 무기보다 **길면** 막는다. 같은 사거리면 둘 다 들어간다.
  그래서 장대(×1.6)와 방패 크기 증가(×2)가 방어 무기로 기능하고, 광선검 관통이 그 카운터다.
- 무적 시간은 기본 공격용과 특수 공격용을 **따로** 잰다. 출혈은 무적을 무시한다.
- 기절과 강제 이동(전기톱 돌진·양날 도끼 낙하) 중에는 조작이 전부 불가하다.

## 폴더 구조

```
scenes/     씬 파일
  title.tscn         타이틀 화면
  lobby.tscn         온라인 로비 (방 열기 / 접속)
  select.tscn        게임 준비 선택 창 (색·머리만. 무기는 라운드마다 고른다)
  player_panel.tscn  선택 창의 플레이어 1인 패널 (양쪽에 재사용)
  main.tscn          전투 화면 (일반 평맵)
  player.tscn        플레이어 캐릭터
scripts/    GDScript
  net.gd             연결·슬롯·설정 동기화 (오토로드 싱글톤 Net)
  game_state.gd      확정된 게임 설정 (오토로드 싱글톤 GameState)
  weapons.gd         무기 17종 표 (설명 + 확정 수치)
  combat.gd          체력·넉백·낙사 등 전투 공통 수치
  jelly_preview.gd   선택 창의 젤리 미리보기 렌더링
resources/  폰트 등 리소스
server/     전용 서버 도커 설정
  Dockerfile         Godot 리눅스 바이너리를 담은 이미지
  entrypoint.sh      프로젝트 복사 → 임포트 → 서버 실행
  docker-compose.yml 포트 매핑(UDP)과 마운트
  .env.example       JELLY_PORT 를 채워 .env 로 복사
```

### 알려진 미완성 지점

- **근접 무기의 기본 공격만 동작한다.** 원거리 기본 공격과 특수 공격(Shift)은 아직 없다.
  지금은 두 젤리가 맞닿으면 서로 무기 데미지가 들어간다.
- 머리 장식은 선택 창에서 고를 수만 있고 전투에 반영되지 않는다.
- 서버 로그에 드물게 `Unable to send packet on channel 0` 이 뜬다. 두 클라이언트가 동시에
  끊길 때만 나오는 ENet 정리 과정의 잡음으로, 진행에는 영향이 없다.
- 맵은 "일반 평맵"만 구현되어 있어서 랜덤을 돌려도 항상 이 맵이 나온다.
- 머리 장식(중절모/왕관/헬멧)은 계획서에 없는 항목이다. 유지할지 팀에서 정해야 한다.

### 아직 정해지지 않은 값

임의로 채우지 않고 비워둔 것들이다.

- **포트 번호** — 로비 입력 칸, `--port`, `JELLY_PORT` 모두 기본값 없음.
- **젤리 스쿼시 연출 수치** — `player.gd` 의 `SQUASH_*` 상수. 아트 작업 때 정하기로 했다.
- **라운드 간 대기 시간** — `main.gd` 의 `ROUND_RESTART_DELAY`. 지금은 라운드 시작 무적
  시간(2초)과 같은 값을 임시로 쓴다.
- **샷건 데미지 감소 기준 거리** — `main.gd` 에 400px 을 임시로 넣었다. 이 거리에서 최소
  데미지(10)가 된다.
- **폭탄이 터지는 시간** — 문서에 "일정 시간" 으로만 적혀 있다.

확정된 값은 `docs/무기_수치_초안.md` 에 정리되어 있다.
